**الاسم الرسمي:** العيادة الاستشارية لأمراض وجراحة المخ والأعصاب والعمود الفقري  
**الطبيب:** د. محمد عبدالله الجرباني  
**العنوان:** صنعاء – شارع تعز – جولة 45، مركز ابن سيناء الطبي التشخيصي  
**الهاتف:** 772070207 – 784545908

## ما يعمل فورًا بعد الرفع إلى GitHub Pages؟

- صفحة رئيسية متجاوبة بالأزرق والأبيض مع صورة الطبيب الأصلية دون تغيير ملامحه.
- 32+ صفحة عربية وإنجليزية، بما فيها 8 صفحات خدمات مفصلة و6 مقالات توعوية وتفاصيل الطبيب، الأسئلة، أوقات الدوام، البحث، التواصل، الحجز، السياسات.
- بحث محلي في صفحات الخدمات والمقالات.
- نموذج يجهز طلب الحجز عبر واتساب، مع التحقق من البيانات. **الطلب لا يعني تأكيد الموعد.**
- أزرار الاتصال المباشر، الخريطة عبر بحث العنوان، تهيئة SEO أساسية، ملف manifest، واجهة مناسبة للجوال وإمكانية وصول محسنة.
- دعم إنجليزي لأهم الصفحات التعريفية. محتوى الصفحات الطبية التفصيلي عربي، ولا تدّعي النسخة الإنجليزية أنها ترجمة لكافة محتويات الموقع.
- صفحات الخدمات والمقالات الأساسية ثابتة وجاهزة للعرض. أوقات الدوام الدقيقة، المؤهلات الطبية، الحسابات الاجتماعية، موقع الدبوس الدقيق غير معتمدة ولم يتم اختلاقها.

## النشر على GitHub Pages — الطريقة الموصى بها

1. فك الضغط وارفع **محتويات المجلد** إلى جذر مستودع GitHub جديد Public (مثل `neuro-clinic`) على الفرع `main`. ارفع مجلد `.github` كاملًا أيضًا؛ إن كان مدير الملفات يخفي المجلدات التي تبدأ بنقطة، فعّل إظهار الملفات المخفية.
2. افتح المستودع > **Settings** > **Pages** > **Build and deployment** > اختر **GitHub Actions**.
3. افتح **Actions** وتحقق من نجاح `Deploy clinic website to GitHub Pages`.
4. رابط الموقع يكون غالبًا `https://USERNAME.github.io/neuro-clinic/`؛ لا يثبت الرابط إلا بعد النشر الفعلي.
5. إذا كان لديك نطاق مخصص يمكن وضع عنوانه مع `/` في **Settings > Secrets and variables > Actions > Variables > SITE_URL** لتحسين canonical/sitemap. إعداد DNS والنطاق يتم بشكل منفصل.

يُنشئ GitHub Actions مجلد النشر و`robots.txt` و`sitemap.xml` وعناوين canonical الصحيحة تلقائيًا. لا تُنشر ملفات قاعدة البيانات أو أداة النشر ضمن الموقع؛ المنشور هو HTML/assets/manifest فقط.

**بديل بسيط:** في Pages اختر Deploy from a branch (main/root). سيعمل الموقع الثابت، ولكن `sitemap.xml` لن يُولّد تلقائيًا قبل تشغيل `scripts/build_sitemap.py` يدويًا، كما قد تصبح ملفات المشروع الأخرى قابلة للعرض للعموم. الخيار الموصى به هو GitHub Actions.

## تجربة الموقع محليًا

```sh
python3 -m http.server 8000
```
ثم افتح `http://localhost:8000/` (لا تستخدم فتح HTML مباشرة من الملفات في وضع file:// لأن بعض وظائف البحث تعتمد على fetch).

## الحجز الافتراضي عبر واتساب

يُنشئ نموذج `booking.html` رسالة مرسلة عند ضغط الزائر عليها، ويفتح واتساب على الرقم `967772070207`. **تحقق مع العيادة من أن هذا الرقم يستقبل واتساب** قبل النشر؛ إذا لم يكن كذلك عدّل `assets/app.js` وابحث عن `wa.me/967772070207`.

يُطلب: الاسم، الهاتف، الخدمة، التاريخ المفضل، الفترة. لا يتم تخزين بيانات المرضى على الموقع الثابت، ولا يُرسل الطلب تلقائيًا قبل استخدام المريض واتساب. يمنع استخدام النموذج في الطوارئ. لا تشجع على إدخال تفاصيل صحية حساسة.

## لوحة التحكم الحقيقية (اختيارية — تتطلب خدمة خارجية)

**تنبيه:** لوحة الإدارة موجودة برمجيًا في `admin.html`، لكنها **غير متصلة وغير قابلة للاستخدام** حتى تنشئ مشروع Supabase بنفسك، وتفعّل قاعدة البيانات، وتمنح صلاحيات موظف معتمد. لا يوجد خادم مستضاف ضمن GitHub Pages.

للتفعيل:

1. أنشئ مشروعًا خاصًا في Supabase مع كلمة مرور قوية، وفعّل تأكيد البريد الإلكتروني وMFA حيثما توفر.
2. شغّل الملف `database/schema.sql` في محرر SQL على **مشروع جديد**. ينشئ الجداول والسياسات RLS. راجع السياسات مع مختص أمني قبل التشغيل الإنتاجي.
3. أنشئ مستخدمًا للموظف من **Authentication > Users**، ثم في SQL Editor امنحه دورًا موثوقًا (استبدل البريد):

   ```sql
   INSERT INTO public.staff_members (user_id, role)
   SELECT id, 'admin' FROM auth.users
   WHERE email = 'admin@yourdomain.example';
   ```

4. عدّل `assets/backend-config.js`: استخدم **Project URL** و **anon/publishable key فقط**. المفتاح العام ليس سرًا؛ الحماية تعتمد على سياسات قاعدة البيانات. **لا تستخدم service_role أو secret key.**
5. لعرض التنبيهات والمقالات المعتمدة والدوام المدخل من قاعدة البيانات، يكفي ضبط `url` و`anonKey`.
6. لتسجيل الحجوزات مباشرة في قاعدة البيانات بدل WhatsApp، غيّر `bookingMode` إلى `supabase`. افحص شروط الخصوصية والحماية من البوتات قبل التفعيل.
7. افتح `admin.html` وسجّل دخول المستخدم الذي حصل على دور. الصلاحيات المتاحة: `admin` و`editor` و`reception`.

**وظائف الإدارة المتاحة بعد التفعيل:** عرض آخر 200 طلب، تعديل حالة الحجز، تصدير CSV محلي، إضافة/تحديث خدمة أو مقال مع مربع اعتماد طبي، نشر تنبيه، وتحديث دوام يومي. تعرض الواجهة الرئيسية الخدمات المعتمدة الجديدة؛ المقالات الإضافية تظهر بقسم المقالات، ونصوصها على صفحة `live-article.html`.

**حدود مهمة قبل التشغيل الفعلي:**
- السماح باستقبال حجوزات عامة عبر API يحتاج حماية إضافية ضد إساءة الاستخدام والطلبات الآلية، مثل Turnstile مع تحقق **خادمي** وEdge Function محددة المعدل؛ التحقق في المتصفح وحده غير كافٍ.
- المنصة لا ترسل تنبيهات SMS ولا توفر دفعًا إلكترونيًا أو حجز وقت مؤكد آليًا؛ هذه أعمال تطوير مستقبلية تحتاج مزود خدمة ونظام جدولة فعلي.
- لا تستخدم لوحة الحجوزات لتخزين التشخيصات أو السجلات الطبية أو التقارير، ويجب وضع سياسات احتفاظ وحذف ونسخ احتياطية واعتماد الإجراءات القانونية المحلية قبل استقبال بيانات حقيقية.
- إدخالات إدارة المحتوى الديناميكي تستخدم مسارات JS: صفحات المقالات الإضافية ليست صفحات ثابتة قابلة للفهرسة SEO؛ يحتاج ذلك إلى بناء صفحات ثابتة أثناء النشر أو منصة SSR لاحقًا.
- عند تفعيل قاعدة البيانات، ينبغي تحديث سياسة الخصوصية المنشورة لشرح تخزين البيانات والاستضافة وفترة الاحتفاظ وحقوق الأفراد قبل استقبال الطلبات.
- الصورة المعتمدة للطبيب مستخرجة من اللافتة التي وفرها صاحب الطلب، ولم يتم تعديل ملامحه.

## الملفات الأساسية

- `index.html` الواجهة الرئيسية.
- `services.html` + `service-*.html` الخدمات وصفحاتها.
- `articles.html` + `article-*.html` المقالات.
- `about.html`, `doctor.html`, `faq.html`, `hours.html`, `booking.html`, `contact.html`, `search.html`.
- `en*.html` الصفحات الإنجليزية.
- `privacy.html`, `terms.html`, `404.html`.
- `admin.html` لوحة الإدارة الاختيارية، **noindex**.
- `assets/style.css`, `assets/app.js`, `assets/extended.js`, `assets/admin.js`.
- `assets/backend-config.js` إعدادات الربط الاختياري.
- `assets/clinic-original-banner.jpg`, `assets/doctor-portrait.jpg` صور مرفقة.
- `database/schema.sql` هيكلة Supabase + RLS.
- `.github/workflows/deploy.yml` إعداد GitHub Pages.
- `scripts/build_sitemap.py` تجهيز SEO وملفات النشر.
